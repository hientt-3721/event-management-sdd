# Implementation Plan: UX Improvements — Real-time Updates, Full i18n, Email/Password Auth & Docs Redesign

**Branch**: `002-ux-improvements` | **Date**: 2026-05-06 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/002-ux-improvements/spec.md`

---

## Summary

Four independent improvements to the existing event management application:

1. **Fix stale UI** — Add `revalidatePath` to `registerTicket`, `cancelTicket`, and `checkInTicket` server actions so ticket counts and statuses update without a manual page refresh.
2. **Full app i18n** — Wire the already-installed `next-intl` library to all 15+ components that currently have hardcoded Vietnamese strings. Move `LangSwitcher` to the global nav.
3. **Email/password login** — Add a second auth method alongside Google OAuth, with two pre-created demo accounts (attendee + organizer) so evaluators can access the app immediately.
4. **Docs redesign** — Rewrite `/docs` as a professional documentation page with a sidebar, terminal code blocks with copy buttons, bilingual toggle, and demo account credentials.

**No schema migrations required.** All changes are additive to the existing Next.js + Supabase stack.

## Implementation Iterations

### Iteration A — Fix Stale UI (Story 1)

**Goal**: Ticket counts and statuses update immediately after mutation without manual page refresh.

**Files**: `src/features/tickets/actions.ts`, `src/features/checkin/actions.ts`, `src/components/tickets/cancel-ticket-button.tsx`

`registerTicket` — after successful RPC, fetch `event_id` from `ticket_types` and call `revalidatePath('/events/${eventId}')`.

`cancelTicket` — add `event_id` to the existing select, then after successful UPDATE call: `revalidatePath('/events/${eventId}')`, `revalidatePath('/tickets')`, `revalidatePath('/tickets/${ticketId}')`.

`checkInTicket` — after RPC returns `status: 'valid'`, query `tickets.ticket_types.event_id` and call `revalidatePath('/organizer/events/${eventId}')`.

`CancelTicketButton` — add `router.refresh()` before `router.push('/tickets')`.

---

### Iteration B — Email/Password Login (Story 3)

**Goal**: Add `signInWithEmail` server action and email/password form to the login page.

**Files**: `src/features/auth/actions.ts`, `src/app/(auth)/login/page.tsx`, `messages/*.json`

Login page keeps server component shell (auth-redirect check) and adds a `LoginForm` Client Component with both Google button and email/password form. `signInWithEmail` validates with zod, calls `supabase.auth.signInWithPassword`, fetches role, redirects to `/organizer` or `/events`.

Error handling uses generic `INVALID_CREDENTIALS` message (OWASP A07 — no user enumeration).

---

### Iteration C — Full App i18n (Story 2)

**Goal**: Every hardcoded Vietnamese string is replaced with `t('key')` via next-intl.

**Files**: 12 pages/components + `messages/vi.json` + `messages/en.json` + `site-nav.tsx` + new `lang-switcher.tsx` in layout/

Pattern: Server Components use `getTranslations('namespace')`, Client Components use `useTranslations('namespace')`. Existing message keys already cover most strings; ~15 new keys needed (see research.md §5).

`SiteNav` reads `NEXT_LOCALE` cookie server-side, renders `<LangSwitcher currentLang={locale} />`.

---

### Iteration D — Docs Redesign (Story 4)

**Goal**: Professional `/docs` page with sidebar, terminal blocks, copy buttons, bilingual content, demo credentials.

**Files**: `src/app/docs/page.tsx` (full rewrite), 3 new client components in `src/components/docs/`

Layout: two-column desktop (sticky sidebar + scrollable content), single-column mobile. Content sections: Introduction, Features, Quick Start (with terminal commands), Demo Accounts, Tech Stack, FAQ.

`TerminalBlock`: dark bg, green text, copy-to-clipboard via `navigator.clipboard.writeText`, "Copied!" flash.

`DemoAccounts`: two cards with email/role visible, password masked with eye-icon toggle.
